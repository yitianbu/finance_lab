# A股尾盘5日策略动态执行模式设计

## 背景

当前 14:50 任务的基础策略是：全A实时快照候选池、5个交易日相似样本验证、Top10轻量实时报价复核、策略状态拦截、核心/进取/观察分层输出。用户的资金执行约束是每天固定投入资金单位 `3`，持有5个交易日，最大资金占用按 `3 * 5 = 15` 估算。

最近真实报告复盘显示，在已保存的完整5日样本中：

- 第一名买3：7个完整买入日，6胜1负，收益/最大占用约 `+23.92%`。
- Top3等权：7个完整买入日，6胜1负，收益/最大占用约 `+20.06%`。

真实样本少，不能直接说明第一名长期一定优于Top3。代理补算显示 Top3 在部分日期更强，尤其当第2、第3名弹性明显高于第一名时。用户目标选择为 `D`：不设硬账户回撤上限，优先追求最终收益最大化，但仍希望跨牛熊尽量提高盈利。

## 目标

设计一个“动态执行模式”，每天仍输出最多3只候选，但额外给出资金执行建议：

- `第一名买3`
- `Top3等权`
- `不新开仓`

攻击模式只作为强行情下的排序增强器，不作为独立开仓系统。

## 非目标

- 不连接券商接口，不执行真实交易。
- 不引入未来数据。
- 不把代理回测结果冒充真实历史推荐。
- 不在本设计阶段修改生产代码。
- 不设置账户层面的硬最大回撤止损，因为用户选择了收益最大化优先。

## 当前问题

1. 自动化提示没有强制执行“先生成 recent_metrics.json，再运行候选脚本”的流程，导致攻击模式和强收益拦截可能没有稳定接入。
2. 第一名和Top3的资金口径此前容易混淆：批次连乘、滚动资金占用、真实报告复盘、代理补算必须分开展示。
3. 攻击模式触发门槛较高，最近30日真实报告因完成样本不足12批不会触发。
4. 如果永远只买第一名，单票踩错会放大亏损；如果永远Top3等权，可能牺牲强行情里的最大收益。

## 方案比较

### 方案A：固定第一名买3

每天只买排序第一名，资金单位 `3` 全部投入该票。

优点：执行简单，真实样本最近略强。

缺点：单票错误暴露最大，熊市或震荡市可能快速回吐。

### 方案B：动态切换第一名/Top3

先判断市场和策略状态，再判断第一名相对Top3是否有显著优势。有优势时买第一名3份，否则Top3等权。

优点：保留强行情单票弹性，同时降低候选分歧时的单票误判风险。

缺点：需要定义清晰、可回测的切换规则。

### 方案C：攻击模式优先

只要攻击模式触发，就尽量买攻击首选3份。

优点：强行情收益弹性最大。

缺点：攻击模式依赖最近已完成样本；真实样本不足时无法触发。若放宽触发条件，容易在震荡或熊市误判。

## 推荐方案

采用方案B：动态切换第一名/Top3。

理由：

- 用户目标是收益最大化，不是最小波动，因此不能简单保守等权。
- 真实样本显示第一名有优势，但样本太少，不能无条件重仓第一名。
- Top3可以作为候选分歧和单票风险较高时的兜底执行方式。
- 攻击模式可以继续存在，但只影响第一名候选的排序，不跳过策略状态拦截。

## 执行决策流程

### 1. 生成滚动真实指标

每天14:50运行前，先根据真实保存报告和已完成5日结果生成 `recent_metrics.json`。该文件至少包含：

- 最近完成批次均值、胜率、最差收益、连续亏损天数。
- 最近30个完成批次的中期均值、胜率、相对最强指数超额、最大回撤。
- 样本不足时必须显式写入样本数，而不是把缺失当作0或空仓。

### 2. 运行基础候选筛选

调用 `scripts/stock_strategy/run_hold5_tail_candidates.py`，传入 `--recent-metrics-json`。脚本仍按现有逻辑完成：

- 全A实时快照候选池。
- 5日相似样本验证。
- 硬剔除和风险分层。
- Top10轻量报价复核。
- 策略状态判断。
- 攻击模式排序增强。

### 3. 判断能否新开仓

如果策略状态为红色，输出 `不新开仓`。

如果无正式核心候选、只有进取研究候选，则允许给出候选，但执行建议默认不能是第一名买3，除非攻击模式触发且候选质量满足额外条件。

### 4. 判断第一名是否显著优于Top3

定义第一名优势检查，初始规则如下：

- 第一名 `avg_return` >= Top3均值。
- 第一名 `win_rate` >= Top3均值 - 2个百分点。
- 第一名 `profit_factor` >= Top3均值 * 0.9。
- 第一名 `reward_risk` >= Top3均值 * 0.9。
- 第一名 `worst_return` 不低于 Top3最差成员太多，容忍差值不超过5个百分点。
- 第一名 `worst_hold_drawdown` >= -22%。
- 第一名没有复核拒绝原因。

全部满足时，执行建议为 `第一名买3`。

不满足时，执行建议为 `Top3等权`。

### 5. 攻击模式处理

攻击模式仍使用现有门槛：

- 最近30个已完成批次中至少12批。
- 中期平均5日收益 >= 6%。
- 中期胜率 >= 55%。
- 相对最强指数超额 >= -2.5%。
- 中期最大回撤 >= -65%。
- 当天Top3候选质量达标。

触发后，攻击首选可替代普通第一名参与“第一名优势检查”。如果攻击首选通过额外风险过滤，则执行建议可以为 `攻击首选买3`。如果不通过，则回退到普通动态切换逻辑。

### 6. 报告输出

日报新增一个“资金执行建议”区块：

```text
建议执行模式：第一名买3 / Top3等权 / 不新开仓
每日计划投入：3
最大5日滚动占用：15
触发原因：第一名优势明显 / 候选分歧较大 / 策略红灯 / 攻击模式触发
攻击模式：未触发 / 已触发，首选 XXX / 样本不足未评估
```

候选表仍保留最多3只，避免用户因为只给1只而遇到价格太高或无法买入的问题。

## 回测与验证口径

必须分三类输出：

1. `真实报告复盘`：只使用保存过的 `hold5_candidates.csv`。
2. `缺失日期补算`：用当前策略历史行情补算，明确标注不是当日真实推荐。
3. `代理长期回测`：用日线代理回放，明确标注非历史14:50盘口。

资金收益统一使用用户确认的口径：

- 每天固定买入资金单位 `3`。
- 第一名模式：单票买 `3`。
- Top3等权：每只买 `1`。
- 持有5个交易日。
- 收益主要报告 `累计盈亏 / 最大滚动占用15`，不再用批次无限复利作为主指标。

## 测试要求

实现时至少覆盖：

- `recent_metrics.json` 生成逻辑：缺失日期不能当空仓。
- 动态执行模式判断：第一名优势明显时买3，否则Top3等权。
- 攻击模式触发但风险不过关时回退。
- 红灯状态下不新开仓。
- 报告输出包含执行建议和资金口径。
- 回测报告区分真实、补算、代理三种口径。

## 风险与限制

- 真实样本目前较少，动态规则需要先作为研究建议运行，不应过度拟合最近7个完整样本。
- 收益最大化会接受更大波动；本设计不设置账户硬回撤线。
- 如果当天没有 `recent_metrics.json`，报告必须明确说明攻击模式和强收益状态拦截未完整评估。
- 历史补算不能替代真实推荐记录。

## 需用户确认

本设计建议先实现“动态执行建议”，但不改变候选生成主逻辑。候选仍输出最多3只；新增的是每天给出资金使用方式。

确认后进入实现计划阶段。
